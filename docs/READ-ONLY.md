# 文件只读与新成果写入

DataLab v0.3 默认保留任务开始前的所有已有文件：原始数据、项目与偏好配置、上下文、旧报告、代码和已有 Python 环境。清洗数据、修改口径、修订报告都生成新版本，不原地覆盖，不重命名或删除原件，也不自动修改原件权限。

## 如何放置文件

建议使用分开的目录：

```text
项目/
  inputs/销售.csv
  config/project.json
  config/preferences.json
  results/分析-001/          # 命令自行创建
  results/看板-001.html
  previews/Word-001/         # 渲染命令自行创建
```

原始数据所在的实际父目录及其子目录都禁止作为输出位置。若原件是 `项目/销售.csv`，则 `项目/results/` 仍在保护范围内，应选择项目外的独立成果目录；不要为了通过检查移动原件。

| 操作 | 新规则 |
|---|---|
| 分析、建模、复算 | `--out` 必须尚不存在；已有空目录也拒绝 |
| Word、HTML、看板、比较、保存验证记录 | 文件名必须是新的；可以在已有成果目录追加新文件 |
| Word 转 PDF/页图 | 新预览目录在输入 DOCX 父目录之外，外部渲染器接收工作副本 |
| 准备依赖 | `bootstrap` 只创建新环境；可直接使用依赖齐全的旧环境，不对其执行安装升级 |
| 打包和安装 | 打包使用全新目录；安装不覆盖已有 `data-lab` 目录 |

旧 `report.html`、`checks.json` 或 DOCX 都保留。需要再次生成时用 `report-v2.html`、`checks-review-001.json`、`报告-v2.docx`。需要修改旧成果包内容时，另建完整副本，保留表格和图片的相对路径，再对新版本做必要验证。没有 `--force` 覆盖开关。

## 自动保护与审计

内置写入函数限制成果目录、拒绝已有文件、检查输入别名与链接，并采用独占新建。只有本次命令创建且仍匹配记录的产物可以在本次命令内更新；下次命令不会继承这一权限。

有限输出任务在成果根目录生成 `audit/file-safety-<唯一ID>.json`。单文件导出的根目录是该文件的父目录。记录包含声明输入的运行前后 SHA-256/状态、已登记新产物及其指纹、执行结果，以及已登记外部写入器的预期位置。`completed` 只表示该文件保护会话结束，不代表数据分析、统计结论或 Word 版式已验收。

记录明确写 `protection: software_guards`、`os_read_only_enforced: false`。它不是电脑所有文件的清单，也不保证记录了第三方程序的全部写入。输入变化会使会话失败，但程序不会尝试恢复原件；哈希不能说明是谁改的。会话开始前被拒绝或成果位置已不可写时，可能没有审计文件。审计包含本地路径，外发前应审阅。

`config`、未指定 `--out` 的 `validate` 只输出到终端，不生成成果审计。`doctor` 使用新临时缓存检查环境。持续运行的 `serve` 没有持久任务审计，而是每次读取核对源文件稳定性；外部业务流程更新源文件属于预期行为，服务自身没有写回原数据接口。

## 软件保护与宿主强隔离

内置工具的保护不能拦截任意额外 Python、SQL、终端命令或第三方库。给脚本工作副本可以减少误操作，但脚本仍可能拥有访问原件的权限。数据库只读也需要数据库账户或连接权限，不能靠本地写入函数代替。

要求更强防护时，由宿主让全部执行进程及其子进程只能读取原件，仅新任务、临时和缓存目录可写。DataLab 不自动安装沙箱，不改 Windows ACL/macOS 权限，也不声称已经实现跨平台只读挂载。Python 入口禁用字节码写入，可控绘图缓存和转换工作使用新位置；这仍不是对所有库和外部程序的系统级约束。

验收时应检查实际宿主：用一次性测试数据验证已有文件和原始目录不能写入，新成果正常生成；覆盖同名文件、空目录、链接别名或目录穿越应失败；拒绝后旧文件指纹保持一致。另用普通自定义脚本验证宿主是否真正拒绝写入。仅内置工具报错不能证明宿主已强制隔离。

具体运行接口与边界见 [Skill 安全参考](../skills/data-lab/references/safety.md)。
